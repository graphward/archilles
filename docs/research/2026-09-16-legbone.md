# 3. Synthesis — inference

Everything below is my inference from the evidence above, not a recorded claim.

## 3a. What failed, and the mechanism

**The dominant failure is not "docs go stale." It is that a reference by *path or name* breaks silently, while a reference by *opaque stable ID* does not.** This is the single sharpest signal in the data, and it is clean:

- References by DEC number: 1,315 in code, ~60 in crate READMEs, dozens in `rules/*.yml` — **0 dangling.**
- References by memory slug: 205 internal + 19 from repo docs — **0 dangling** (slugs never move; the store is flat, with no directories to refactor).
- References by file path or crate name: `legbone_protocol`, `sim-core`, `sim/src/lib.rs`, `server-bevy/`, `docs/DECISIONS.md`, `client/`, `proto/legbone.proto`, `tools/wire_parity.py` — **broken in `README.md`, `CLAUDE.md`, `MAP.md`, `clippy.toml`, `.debtmap.toml`, `fence.py`, `HARNESS-DESIGN.md`, Dockerfile.sim, deploy.yml, and ~222 Shrimp ticket anchors.**

The mechanism is asymmetric feedback. A path reference inside prose has no reader that fails when the path dies; a path reference inside a *glob* (`fence.py`'s shared-interface list, an ast-grep `files:` clause) also fails silently — it just stops matching. The project discovered this and named it: "tendril." But it only ever built tendril inventories reactively, per incident, and `INBOX.md:68` records the sweep list growing each time (code → serialized data → deploy artifacts → operating cards → ticket anchors). There was never a mechanical closure, because the thing that would have closed it — DEC-0071's `harness-auditor` — was accepted and never built. **The record specified its own drift detector and then drifted, undetected, for the reason the detector was meant to catch.**

**The second mechanism is severity-tiering as a decay channel.** Every warning-tier check in this repo has a permanent, growing backlog and an unkept promise: 3 ast-grep rules at `severity: warning` with 30 violations each carrying "flip to error once the existing hits are cleaned"; `record_lint.py` with 0 errors and 59 warnings including 23 research docs 50–68 days past their `Distilled-into:` stamp. Every error-tier check has zero violations. A non-blocking finding in this system is indistinguishable from no finding at all. The soft tier did not act as a runway to the hard tier; it acted as a landfill.

**The third mechanism is distillation from the wrong source.** `MAP.md` was generated on 2026-07-10 by distilling the 178-entry DEC ledger. Its "Debug replication … NOT gated today (named risk)" line was already false — the gate had shipped nine days earlier. The ledger was correct *as history*; the card claimed to be *current truth* but inherited the ledger's timestamp. `docs/MAP-DISTILLATION-NOTES.md` — itself headed "delete after review" and never deleted — shows the distillation was a judgment pass over DEC bodies, not a verification pass against code. Any record that claims currency but is derived from a historical record will be stale on the day it ships.

**Fourth: every hierarchy attempt was superseded by the next one within ~3 weeks, and the meta-doc declaring the hierarchy died with it.** `docs/_archive/README.md` ("Three tiers; don't add a fourth source that overlaps these") governed for five days. The DEC ledger's "This is the ONLY architecture document" governed for four weeks. The 2026-07-18 squash's "THE one architecture doc" governed for nine days before `MAP.md` was carrying operational truth and `ARCHITECTURE.md` §3's roster had gone wrong. The pattern is that consolidation passes produced a *new* canonical artifact rather than deleting the old ones, so each generation left a fossil that still reads authoritative — and the project ended with two archive roots, two `ARCHITECTURE.md`s, and a README pointing at a `docs/DECISIONS.md` that has moved twice.

**Fifth, and structurally: the most load-bearing records live outside version control.** The 85-file memory store — by every measure the healthiest record here — is in `~/.claude/`, not a git repo: no history, no diff, no blame, no review, invisible to every gate. `.claude/epics/CAPFRONT.md`, the map of the final active arc, is explicitly gitignored. The Shrimp backlog is a 460-entry JSON blob that no gate reads. The three records agents actually worked from were the three nothing could check.

## 3b. What succeeded, and why

**`tools/dep_graph_lint.py` is the one unambiguous success, and its design is the transferable lesson.** It does not *duplicate* the architecture rule — it **parses the doc as its config**: "this block is the single source; the lint parses it, so changing the law means editing this doc" (`ARCHITECTURE.md:232`). The result is visible fifty lines apart in the same file: §5's fenced `graph-law` block is exactly accurate (29 members, all classified, gate green), while §3's prose roster immediately above it calls `ng9_world` dissolved, omits two crates, and miscounts the rest by six. **Same file, same authors, same week. The difference is that one block had a parser and the other had a reader.** Drift is not a property of documents; it is a property of the absence of a consumer that fails.

**`rules/*.yml` is the second success, for a different reason: the rules were *maintained* because they were load-bearing and dated.** Each carries an origin date, the incident that caused it, the DEC it derives from, and a decay condition. The 2026-07-24 skeptic pass swept every `files:` glob in the directory to repoint after DEC-0181 — a deliberate tendril sweep on `rules/` that nobody performed on `README.md`, `clippy.toml`, or `fence.py`. Crucially, `sgconfig.yml:3` records the design rule that made them survivable: "**These are a DERIVED VIEW of the DECs — they cite DEC numbers, never a DEC's status.**" A derived view that copies an ID stays valid across supersession; one that copies a status goes wrong the moment the status changes.

**The memory store succeeded for reasons orthogonal to tooling.** Flat namespace of stable slugs (nothing to rename); one claim per file with the claim in the `description` frontmatter (so the index and any search result carries the assertion, not just a pointer); a fixed body shape (`Why` / `How to apply`) that forces the *reason* to travel with the rule; append-only amendment markers (`UPDATE`, `CORRECTION`, `RELAPSE`, `2nd occurrence`) that keep reversals visible in place; and above all an explicit **self-invalidation header convention** — `HISTORICAL guard`, `SUPERSEDED/DELETED`, `STALENESS (current):`, "**Do NOT act on any directives that point to `server/` code**". No repo doc ever adopted that convention. It is the cheapest drift mitigation in the whole project and it was invented on the side that had no enforcement at all.

**`RELAPSE` and `2nd occurrence` are the most valuable markers in the corpus** and I have not seen their equivalent in any conventional decision format. `lane-infra-leak.md:3` ("2nd occurrence"), `seam-size-slices-builders-fan-out.md:31` ("RELAPSE … James: 'constant linking is killing progress man'"), `no-domain-plugins-mechanism-first.md:10` ("twice in one day"), `local-verification-ceiling-cargo-check.md:27` ("2nd occurrence"). A record that counts its own recurrences is measuring whether it is working. That count is the only honest signal for *decay* — whether a rule's failure mode has stopped reproducing — which is exactly what `CLAUDE.md:69-73` requires and what the never-scheduled monthly prune cron (still sitting in `INBOX.md:125` from 2026-07-10) was supposed to act on.

**`scripts/map-lint.sh` succeeded at the one thing it measures and reveals the ceiling of size-based enforcement.** MAP.md is at exactly 120/120 and CLAUDE.md at 73/80 — the cap is real and binding, and "the cap is enforced, not prose" (`map-lint.sh:4`) is a genuine insight: a size budget forces deletion, which is the only reliable anti-accretion mechanism. But it is content-blind. MAP.md is at its cap *and* carries a two-month-stale risk claim and a contradicted adopted-seam line. A budget makes a document short; it does nothing to make it true. Note also that `map-lint.sh` was introduced as the "successor to `tools/record_lint.py`" and is strictly weaker than its predecessor — the succession traded a supersession-graph checker for a line counter.

## 3c. What this suggests

**(a) How decisions should be stored.**

Store the *decision* as an immutable, opaque-ID record and everything else as a derived view that cites the ID, never the status or the prose. The DEC ledger's ID scheme is the one referencing mechanism in this project with a perfect survival record across three crate-renaming refactors, two architecture squashes, and a language port. Corollaries the evidence supports:

- **Never reference a decision by file path.** Paths are the failure vector; IDs are not. If the store must be a filesystem, use a flat namespace of stable slugs (the memory store), not a directory tree (the `docs/` tree, which produced `docs/archive/` vs `docs/_archive/` and two `ARCHITECTURE.md`s).
- **The assertion belongs in the index entry, not behind a link.** Memory `description` frontmatter carries the claim; `MEMORY.md` is readable as a whole without opening a file. The DEC ledger's digest was deleted in the squash and nothing replaced it at that altitude.
- **Separate "history" from "current truth" physically, and derive the current view mechanically or not at all.** The 07-18 squash got the separation right (append-only ledger demoted, one current record promoted) and the derivation wrong (hand-distilled prose). `MAP.md`'s stale risk line is the direct cost.
- **Status is not a copyable field.** Every drift instance where a derived artifact carried a decision's *status* went wrong; every one that carried only the *ID* stayed right. DEC-0071 stated this as a standing invariant and it held wherever it was followed.
- **Version-control the store.** The best record here has no history, no diff, and no review — which also means no way to ask "when did this become wrong," the question the whole drift problem reduces to.

**(b) What must be enforced mechanically vs. left to review.**

The line the evidence draws is not "important vs. unimportant." It is **decidable-from-the-artifact vs. requiring judgment about intent** — and the practical test is whether you can write a consumer that *fails* on a machine.

Mechanical, non-negotiably:
- **Reference resolution.** Every ID, path, crate name, agent name, ticket anchor, and cross-link cited by any governed artifact. This is pure graph-checking and it is the exact failure class that dominated here. DEC-0071 specified it precisely and its absence explains most of section 1.
- **Structural invariants expressible over the code graph** — dependency tiers, forbidden identifiers, forbidden call shapes. `dep_graph_lint` + `convention12_lint` + the six error-tier ast-grep rules: zero violations, no exceptions, no drift.
- **Size budgets on anything claiming to be current truth.** Cheap, and the only force that causes deletion.
- **Supersession graph symmetry** — `record_lint` already detects one-directional supersession; it just reports it at a tier nobody reads.
- **Recurrence counting.** A record should know how many times its failure mode has re-fired; that number, not a calendar, should drive decay.

Review only:
- Whether a decision is *right*; whether an exception is honest (the skeptic's actual job: "Is every quality suppression's written justification real, or an excuse?"); whether a concept has been correctly re-framed (`spec-pass-before-tickets`: "a census measures movability; the value lives in reframability" — no machine finds that); whether a boundary is in the right place.

Two hard constraints the evidence imposes on any such scheme:

1. **No third tier.** Warning-severity is where rules go to die. A check either blocks or it is a report nobody acts on. If something is worth checking and cannot block yet, it needs an owner and a date, not a severity level.
2. **Enforcement must be out-priced, not added.** James's position is explicit and was proven right twice: "**If the engine's declarative path needs a cop to get used, the path isn't good enough yet**" and "if a guard still catches violations after the paved road ships, the road failed and THAT is the bug." The counter-constraint from `dont-justify-out-of-guards` is equally important: a guard under construction must not be dismantled by an agent citing that same principle. **The reconciliation the project landed on — guards are transition ratchets carrying an expiry, and the expiry is data, not sentiment — is the right shape, and the only reason it failed here is that the monthly prune cron was never scheduled.** The decay discipline was fully specified in `CLAUDE.md:69-73`, stamped onto 61 individual rules, and never once executed.

**(c) The vocabulary of relationships that actually mattered.**

Out of ~20 relationship verbs in use, only a handful carried operational weight. Ranked by observed load:

1. **`supersedes` / `superseded-by`** — the workhorse, and the one that most needs to be *bidirectional and mechanical*. Every failure mode here was one-directional: the superseding side knew, the superseded side stayed live-looking and kept instructing agents to run deleted commands. This relation must be stored once and rendered on both ends.
2. **`blocked-by`** — and specifically James's ruling that it is **an annotation, not an edge**: "Cross-arc blocks live in notes as 'BLOCKED-BY:', not fake dependency edges." Real dependency edges are for scheduling within one arc; cross-cutting blocks are prose with a named blocker. Conflating them corrupts the frontier computation. `HANDOFF.md` demonstrates the working form: "BLOCKER only James clears: TYPE-TIERS."
3. **`refines` / `extends`** (33 uses combined) — the most common relation by far, and the one no conventional ADR format has. Most records here did not *replace* a predecessor; they narrowed, tempered, or added an axis to it. Forcing that into supersede/accept loses the information. `paved-road-over-police.md:38` needs all three verbs in one sentence: "Refines X + Y; **tempers** the enforcement half of Z."
4. **`derived-view-of`** — the relation that actually prevented drift when honored (`sgconfig.yml:3`), and whose *unenforced* form is DEC-0071, the largest single failure. This should be a first-class, machine-checked edge: view → source, with the view permitted to cite IDs and forbidden to restate status.
5. **`realizes`** (5 uses) — connects a principle to the concrete work that discharges it. Underused but exactly the missing link between the P-ledger and the CAPFRONT epic.
6. **`recurrence` / `2nd occurrence` / `RELAPSE`** — not a relation between records but between a record and reality. **This is the one the project invented and conventional formats lack entirely**, and it is the only field that can honestly drive expiry.

What proved near-worthless: `see also` (zero literal uses; the generic `See` bucket is undirected and carries nothing a link graph doesn't), `informs` (1), `depends on` (2 — always where `blocked-by` or a real Cargo edge was meant). A vocabulary of roughly six typed relations covers everything 85 memory files and 181 decisions needed; anything richer went unused.

**One last observation.** The two records with perfect referential integrity — the DEC ledger and the memory store — achieved it by opposite routes. The ledger is append-only, immutable, mechanically linted, and version-controlled, and it is *inert*: frozen 2026-07-18, correct because nothing can change it. The memory store is freely edited in place, has no history, no linter, and no git, and it is the record agents actually worked from daily and the one that stayed true. The difference between them is not tooling. It is that memory files were **rewritten whenever reality moved**, and carried a convention for confessing when they had not been. Everything in between — README, MAP, the operating cards, the crate roster prose, the Shrimp anchors — was edited often enough to look maintained and not often enough to be right. That middle band is where all the damage lives.
