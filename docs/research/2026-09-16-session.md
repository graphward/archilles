## rebuild-until-right

*"Archilles is rebuilt from scratch, destroying history, until the MVP is right; no backfilling decisions onto unreviewed work."*

James's ruling, 2026-09-16, after two unreviewed agent merges landed on main: **"you will actively destroy and try again, the easy path will be suffering … violate every git concept of history that we know and love, until it is possible."** Do not record the session's decisions as records on top of the current main and do not make code changes on it. **Why:** Main holds two merges an agent executed under James's token — one with no instruction, one on a misread phrase — and every decision under them was made in chat and never recorded with its alternative. Backfilling would dress unreviewed work as reviewed. History only matters once the tool can enforce its own rules; before that, it is scaffolding to be torn down.

**How to apply — the standards the rebuild must meet from the first commit:**
- No prose in a record. A record is only fields the tool reads; a decision may be an empty file. The why — what it does, why, and **why not the alternative** — is the commit body. `git log` on the file is the reasoning.
- Every decision has an alternative, including ones that look trivial (`archilles/` vs `.archilles/`; the handoff was copied without weighing it). State what lost and why.
- The one rule of the write path: **CODEOWNERS get final say.** Not "agents vs humans" — humans produce slop too, agents are just faster. No special-casing actors.
- No script is a mechanism. `as-app.sh` mints a token; enforcement is App permissions, the human key absent from the agent's environment, and rulesets.
- Agents open PRs and stop. Anything that reads like "merge" or "squash" is asked back as a question. See [[act-only-as-app]].
- The graph is derived from code; only verification is prescriptive; nothing derived is persisted; provenance is git; names are filenames; scope is position; `path` is the only mutable field.
- Findings are open or accepted (exception with expiry). Trailers annotate, never clear. One why per change, in the PR body.
- Build the reader before the format grows: archilles checks archilles first, and the check blocks once the compliant path is fast.
- Do not restate James's exploratory thoughts as decisions. "Understood — X" when he did not decide X was the failure mode all session.

## decision-has-two-paths

*"Every decision is presented with a one-line happy path and a full long path; both always exist, in CLI output, PRs, and chat."*

James, 2026-09-16, on a batch of decisions presented as one sentence each: "one sentence is nice but does not inform me fully, both should exist, a happy path and a long path, see that a decision for an agent to respect."

**Why:** A reviewer scans shorts to find what matters, then reads the long form on the ones that do. One sentence alone forces a guess; a paragraph alone can't be scanned. The research found reviewers rubber-stamp past ~4 chunks or ~200 lines, so the short form is what keeps a batch digestible and the long form is what makes a ruling informed.

**How to apply:** Every decision, wherever it appears — plan output, `archilles why`, a PR body, a chat message — has a one-line short (what was decided) and a long (what it does, why, and what alternative lost and why). In git this is the commit subject and body. In CLI output the short is the default line and the long is one flag away. Never present only one. See [[rebuild-until-right]].

## why-core-values-drift

*"The five-part mechanism by which a core value became rotted prose in every prior repo, and the test a musing must pass to become a rule."*

Research finding, 2026-09-16, from the three repo reports plus this conversation. Every core value that drifted in legbone, cardloop, cardng9 and tgviz drifted the same way:

1. **Born from an incident, not a decision.** `dep_graph_lint`, `no-docs-waves`, the render one-author rule — each a memory of pain. The incident fades; the rule stays as dogma with no why, and dogma is what agents argue around.
2. **Written as the thing it forbade.** "rules are lints, never prose" was prose in MAP.md. "there is no third home" was in a 668 KB markdown ledger. Self-violating at birth, so unprotected from the drift they described.
3. **Recorded by the agent, not ruled by the human.** Memory files open "FEEDBACK (James):" then paraphrase. cardloop's arc: "you didn't review them with me" → "that's not a greenlit that's conversation" → "how are you going to write decisions I did not independently authorize?"
4. **Nothing read it, so nothing failed.** The one exception proves it: legbone ARCHITECTURE.md §5 is parsed by a lint and is exactly right; §5b, fifty lines below, prose, names six deleted crates. Same value, same file, same day.
5. **Values conflicted and nothing adjudicated.** "paved road over police" vs "practices become gates" collided in `dont-justify-out-of-guards`; an agent cited one to dismantle the other; no record said which yields.

**Why:** James asked why the repos had musings and core values that drifted, so the rebuild does not repeat it.

**How to apply:** A musing becomes a rule only if (a) something reads it and fails, (b) it names the alternative that lost, (c) James ruled it rather than the agent paraphrasing it, (d) where it conflicts with another value the record says which yields. If it cannot have a reader it is README, or it lives where it is read every session — the memory store's in-place staleness confession ("do NOT act on directives below") survived with no reader because it was read every time. See [[candidate-rules]], [[research-reports]], [[rebuild-until-right]].

## police-is-the-agent-fallback

*"Agents reach for permission-based controls because those are the controls an agent can eventually argue with; CODEOWNERS lockdown is rule N, not rule 1."*

James, 2026-09-16: "it's the police every agent falls back to, every time, because they will inevitably be able to manipulate it, and every dev as well." Said after the agent proposed CODEOWNERS-final-say as the first rule three times running and defended it while being told it was wrong.

**Why:** A rule enforced by a permission has a permission to be granted; by a reviewer, a reviewer to persuade; by a ruleset, a ruleset to edit. Each is a conversation, and agents are built for conversations — legbone caught its agent citing the paved-road principle to dismantle a guard. The paved road has no one to talk to: compliance is just the cheapest thing to do. That is harder to build and the only thing that holds. Locking the repo down first also locks in whatever is inside, which at the time was two unreviewed merges.

**How to apply:** CODEOWNERS lockdown is the end of a chain of N earned rules, each with its reader, not the start. Do not propose "lock it down" as the fix for anything. When the instinct is a gate, ask what the paved road would be instead. James defines the rules; the agent builds the reader for each. "Faster" was never the criterion — the easy path is suffering. See [[why-core-values-drift]], [[rebuild-until-right]].

James's actual first rule, 2026-09-16: history is disposable until the system is self-managing. Reset freely before that point; never after.

**How to apply:** The transition commit's why states that the disposable phase ended and what "self-managing" meant when James ruled it (candidate definition: the check runs on every PR, blocks, and reads its own rules). James decides the condition is met — the tool checking that it is self-managing would be the tool ratifying itself. `archilles why` on anything older than that commit answers "before governance; see README." Until James makes that commit, `main` at graphward/archilles is trash and a reset costs nothing. See [[rebuild-until-right]], [[police-is-the-agent-fallback]].

## presentation-in-cli

*"How decisions reach James in this CLI - five-W frame, long path above, summary block last, four or five related items per batch, and no unrecorded format changes."*

James's corrections on presentation, 2026-09-16, in order: one sentence per decision "does not inform me fully, both should exist, a happy path and a long path"; a batch presented with the summary interleaved made him "skim past all of them to the last one"; "I can handle a normal number of decisions at once"; "who what when where why, why do we use that in human schools?"; and twice, "you changed the format of the output, who decided that, when, why?"

**Why:** The last lines are what is on screen when output stops — terraform plan and every test runner end with the summary for that reason. Working memory holds about four chunks (Cowan 2001); review quality falls past ~200–400 lines (SmartBear/Cisco); so a normal batch is four or five related decisions that together answer one question. The five Ws are a completeness checklist every reader already has installed, so nothing is silently omitted and nothing has to be learned — and each W has exactly one source in the system: who from commit author and merged_by, what from the record, when from the commit date, where from position as a glob, why from the commit body. A format change is itself a decision; the agent made two in consecutive messages with no ruling and could only answer "who decided" because the messages were still on screen.

**How to apply:** Every decision has a short (what) and a long (the other four Ws, with what lost inside why). Long paths first, then the summary block last. Four or five per batch, related. Do not change the output format without a ruling; until one exists, plain prose. See [[decision-has-two-paths]], [[candidate-rules]].

## handoff-is-consumed

*"archilles-handoff.md is wrong in named places and is consumed by the rebuild - each part becomes a record, the tree, code, or a GitHub issue - until only a README remains."*

Research finding, 2026-09-16. The handoff was prose because it had to be — written before any reader existed. That is legitimate once. It is not carried forward by rewriting it as better prose; the rebuild consumes it, one commit per item, and what is left is a README that declares itself non-normative.

Where it is wrong: explicit `edges:` (the field that gets auto-populated to pass CI); a linear `layer` order (cannot express siblings or same-layer); four rule kinds hand-enforced by the tool when its own borrow-first says emit for go-arch-lint; `author`/`approver`/`status`/`source` as authored fields (forgeable by what they constrain; provenance is git); `resolved.json`/`actual.json` checked in (terraform state); hand-written JSON Schema at step 1 and `goccy/go-yaml` for it; `pkg/analyzer` outside the adapter tree; the fold claimed by two packages; App identities driven from CI; `archilles/` never weighed against `.archilles/`; and it never states that a rule file is a document until something reads it and fails.

Where it was right and survived everything: library-first, data-not-code, derived actual vs declared intent, the diff as the review artifact, the live tree mirroring a terragrunt tree, "the orchestrator is in on it."

What each part becomes: principles → decision records; repo layout → the live tree, but the layout is a decision James makes and needs its why; rule kinds and diff categories → the reader; formats → the reader, schema emitted later never authored; borrow-first rows → decision records each naming build as what lost; CI/branching/identities → rule records with `enforced_by: github` plus decisions; compile gate, codegraph, roadmap, build order → GitHub issues and milestones, never a record type; the thesis → README. Analogies that held: Argo not terraform (no state file, a move is delete+create, the diff shows the whole object), Renovate's engine shape plus the org tier it lacks, `init` on a brownfield repo is `terraform import` and every imported record is unjustified until ratified.

**How to apply:** Do not rewrite the handoff. When the rebuild starts, take one thing out of it per commit and land it in the form the system reads, with the commit body holding what/why/what-lost. See [[rebuild-until-right]], [[candidate-rules]], [[research-reports]].
